Comics Cuz Yes — deploy checklist

Eleven steps. Roughly 45 minutes, most of it waiting on DNS.

0 of 11
Fill in the boxes as you go. Every command below rewrites itself to use your real values, so you can copy them straight across. Nothing is saved anywhere — keep this tab open until you finish, and use Save my values at the bottom before you close it.

1. Unpack the project

Everything else runs from inside this folder.

Unzip comicscuzyes.zip somewhere sensible — alongside your Bluehost Migration folder is fine. Then:

cd path/to/comicscuzyes
npm install
npx @11ty/eleventy --serve

Open http://localhost:8080. You should see the placeholder comics. Stop it with Ctrl-C when you've had a look.

Check Node first node --version should print 18 or higher. If not, brew install node.

2. Create the GitHub repo

This is the permanent archive. Every approved comic lands here as a plain file.

Make a new private repo on GitHub. Don't add a README or .gitignore — the folder already has what it needs.

cd path/to/comicscuzyes
git init
git add .
git commit -m "Comics Cuz Yes"
git branch -M main
git remote add origin https://github.com/YOUR-REPO.git
git push -u origin main

3. Make a GitHub token

This is what the Worker uses to commit an approved comic. It's the most sensitive value here.

GitHub → your avatar → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.

  • Repository access: Only select repositories → pick just this one
  • Permissions: Repository permissions → Contents: Read and write. Nothing else. Leave every other permission on "No access".
  • Expiration: pick a real date and put it in your calendar
Copy it now GitHub shows the token exactly once. Paste it somewhere temporary — you'll use it in step 7.

4. Point Cloudflare Pages at the repo

This is what actually serves the site. It rebuilds on every push.

Cloudflare dashboard → Workers & Pages → Create → Pages → Connect to Git → pick the repo.

  • Framework preset: None
  • Build command: npx @11ty/eleventy
  • Build output directory: _site

Save and deploy. You'll get a *.pages.dev URL — open it and confirm the placeholder comics are there. Then Custom domains → add comicscuzyes.com and www.comicscuzyes.com. Since the domain is already in this Cloudflare account, the DNS records get created for you.

5. Set up Resend for the notification email

This is how the approval reaches you. Free tier is far more than enough.

  1. Sign up at resend.com and add comicscuzyes.com as a domain.
  2. It gives you a few DNS records. Add them in Cloudflare DNS for comicscuzyes.com.
  3. Wait for Resend to show the domain as verified — usually minutes.
  4. API Keys → create one with Sending access.
Only touch comicscuzyes.com You have mail records on other domains. Make sure you're in the right zone before adding anything — a stray SPF record in the wrong place breaks real email.

6. Generate the two secrets

One lets her app submit. The other signs your approve links. They must be different.

Press the button — these are generated in your own browser and go nowhere else.

If you'd rather use your own terminal openssl rand -hex 24 and openssl rand -hex 32.

7. Create the KV store and deploy the Worker

KV holds pending comics. Nothing here is public.

cd path/to/comicscuzyes/worker
npx wrangler login
npx wrangler kv namespace create PENDING

That prints an id. Paste it here:

Now open worker/wrangler.toml and make the top of it look like this:

[[kv_namespaces]]
binding = "PENDING"
id = "YOUR-KV-ID"

[vars]
GH_REPO = "YOUR-REPO"
GH_BRANCH = "main"
NOTIFY_TO = "you@example.com"
NOTIFY_FROM = "Comics Cuz Yes <comics@comicscuzyes.com>"
ACCESS_TEAM = "fill-this-in-at-step-9"
ACCESS_AUD = "fill-this-in-at-step-9"

Then set the four secrets. Each command prompts you to paste the value:

npx wrangler secret put SUBMIT_SECRET
npx wrangler secret put APPROVAL_SECRET
npx wrangler secret put GH_TOKEN
npx wrangler secret put RESEND_KEY
npx wrangler deploy
What to paste at each prompt SUBMIT_SECRET and APPROVAL_SECRET from step 6, GH_TOKEN from step 3, RESEND_KEY from step 5.

8. Give the Worker its own hostname

Her app needs a stable address to POST to.

Cloudflare → Workers & Pages → comicscuzyes-publisher → Settings → Domains & Routes → Add → Custom domain → publish.comicscuzyes.com.

Confirm it's alive:

curl https://publish.comicscuzyes.com/

It should answer "comicscuzyes publisher. Nothing to see here."

9. Cloudflare Access — the no-more-PINs part

This is the piece that lets you approve with a Google click instead of a code.

First, add Google as a login method. Zero Trust → Settings → Authentication → Login methods → Add new → Google. It walks you through creating an OAuth client in Google Cloud — a plain Gmail account is fine, you do not need Workspace.

Then create the application. Zero Trust → Access → Applications → Add an application → Self-hosted:

  • Subdomain publish, domain comicscuzyes.com, path review
  • Session Duration: 1 month — the default is 24 hours, change it
  • Login methods: Google only (untick One-time PIN)
  • Policy: Allow → Include → Emails → your address

Open the app's Overview tab and copy the Application Audience (AUD) Tag.

Put both into wrangler.toml and redeploy:

ACCESS_TEAM = "your-team"
ACCESS_AUD = "your-aud-tag"
npx wrangler deploy
Don't skip the redeploy Until those two values are live, the Worker refuses every request to /review — including yours. The one-click email links still work.

10. Test the whole path yourself

Do this before you hand her anything, so the first thing she sees is it working.

Submit a comic by hand, as if you were her app:

curl -X POST https://publish.comicscuzyes.com/submit \
  -H "Authorization: Bearer YOUR-SUBMIT-SECRET" \
  -F "image=@src/static/images/comics/hello-world.png" \
  -F "title=Test comic" \
  -F "note=ignore me"

You should get {"ok":true,...} back, and an email within a few seconds. Click Publish it in the email. Wait about a minute for Pages to rebuild, then load comicscuzyes.com — the test comic should be the front page.

Then visit publish.comicscuzyes.com/review to confirm Google login works and the queue is empty. Finally, delete the test:

git pull
git rm src/comics/*test-comic.md src/static/images/comics/test-comic.png
git commit -m "Remove test" && git push
If the email never arrives npx wrangler tail in the worker folder shows live logs. A Resend rejection almost always means the domain isn't verified yet.

11. Set up her Mac and iPad

The part she actually touches.

The droplet app — run this on her MacBook (or yours, then AirDrop the app):

cd path/to/comicscuzyes/clients
./build-droplet.sh YOUR-SUBMIT-SECRET

Drag Send to Comics Cuz Yes.app into her Dock. Drop a PNG on it. First launch may need a right-click → Open.

This one is untested It was written on Linux, where AppleScript can't be compiled. If osacompile throws an error, paste it to me and I'll fix it.

The Shortcut — do this once on her Mac and it syncs to her iPad:

  1. Shortcuts → + → name it Send to Comics Cuz Yes
  2. Details (ⓘ) → tick Show in Share Sheet → accepted input: Images
  3. Add Ask for Input → Text → "What's this comic called?"
  4. Add Get Contents of URL → https://publish.comicscuzyes.com/submit → Method POST
    • Header Authorization = Bearer YOUR-SUBMIT-SECRET
    • Body Form: image = File → Shortcut Input; title = Text → Provided Input
  5. Add Show Notification → "Sent to Dad!"
  6. Run it once from Photos to grant permissions

Writes a text file with everything you've entered. Keep it somewhere safe — it contains secrets.

If something goes sideways, npx wrangler tail in the worker folder shows live logs, and node test.mjs re-runs the 22 checks offline.
